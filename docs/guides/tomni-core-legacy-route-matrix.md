# Tomni Core legacy HTTP/WS route matrix

Audit date: 2026-07-17. Scope: Electron desktop source under `packages/desktop/src`. External provider APIs and documentation-only examples are excluded. `compat` remains the desktop default; this audit does not authorize native-only cutover.

## Acceptance rule

A family may leave compatibility mode only when every desktop caller has a Main/Rust owner, persisted data is migrated, failure semantics are covered, and its renderer/Main integration tests pass. WebUI network clients may continue using REST/WS through a compatibility gateway even after desktop callers become IPC-native.

## Main-process provider subset migrated in this phase

The following no longer read `GET /api/providers` during normal desktop execution and now use `listReadyProviders()` from the encrypted Tomni provider store:

- IDE chat and knowledge graph
- Browser agent chat
- Studio chat
- Testing scenario generation and application detection
- Automation chat and AI node execution
- Monitor analyzer and Manager
- Realtime Knowledge embedding
- Pricing recommendations
- MakeVideo
- Company agent-pool provider discovery

Only `tomnyProviderBridge.ts` and `runBackendMigrations.ts` retain `GET /api/providers`, strictly for one-time compatibility import. This boundary is intentional until old provider data migration is accepted.

## Cutover blockers

1. WebUI/auth, Channels, Extensions and Hub still require production REST/WS behavior.
2. Conversation adjuncts and message search still require SQLite/schema compatibility; Agent/Assistant catalog data now has native durable stores with one-shot compatibility import.
3. Office preview servers and proxy URLs are network services, not simple renderer IPC replacements.
4. `/ws` multiplexes multiple event families and must be replaced by a versioned gateway or native emitters plus a WebUI gateway.
5. Native-only must not become default until these blockers have acceptance tests and rollback coverage.
